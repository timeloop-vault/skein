  successor issue, then close. Fixed issues close as completed, the
  rest as not planned.
- **Reword**: a comment headed "Triage 2026-11-17" stating the current
  scope and where the code lives now. Issue bodies are left alone,
  with one exception below.
- **Epic checklists** (#575, #751, #674, #257, #305): tick the boxes of
  children that are closed and add missing children. This is a body
  edit; say no in a comment if you prefer a comment instead.
- **#302** closes into `docs/backlog.md`, which means a small docs
  commit on this branch (the surface table and the reader-view idea).
- **Labels**: add `priority-high` to the seven issues marked high.
  No other label changes are proposed. The label stays the source of
  truth for the order of attack; the board's Priority field mirrors it
  (High on the board means the label is set).

## Proposed project board

**Name:** Skein roadmap, under the `timeloop-vault` owner, linked to
the repository. Created private; making it public is your choice.

**Fields**

| Field | Values |
| --- | --- |
| Status | Backlog, Next, In progress, In review, Done |
| Priority | High, Medium, Low, Parked |
| Track | skeind, harness-telemetry, opencode-v2, cost, agent-api, review, design-pane, rooms-ui, perf, code-health |
| Phase (skeind only) | P2a, Thin client, P2b, P3, P3b, P4, P5, P6 |

Bug or enhancement stays a label, not a field. Epics go on the board
like any other issue, so a track shows its epic beside its children.

**Initial values:** the 69 issues that stay open are added with the
track and priority from the tables above, plus any new issues that are
approved. Status is "Next" for the items in the "Work next" list and
"Backlog" for the rest. #583 sits in "In review" until the dogfood pass
closes it.

**Views**

1. *Board*: by Status, Parked items hidden.
2. *By track*: table grouped by Track, sorted by Priority.
3. *Work next*: table filtered to Priority High or Status Next.
4. *skeind*: table filtered to the skeind track, grouped by Phase.

A limit to know about: GitHub's API can create a project, its fields
and its items, but may not be able to create or configure views. If
that holds when applying, the views are a few clicks for you in the
web UI and the exact settings will be listed for you.

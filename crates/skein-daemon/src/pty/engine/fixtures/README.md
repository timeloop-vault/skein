# Engine replay fixtures (#793)

`claude-session.json` is one real Claude Code 2.1.327 session (model haiku,
a neutral prompt), recorded 2026-11-18 through portable-pty/ConPTY on
Windows at 120x30. It is scrubbed with same-byte-length, same-width
replacements (the user path in the window title, the session id in a link,
the plan name in the banner, the user's status-line text), so event sizes
and cursor arithmetic are unchanged. The scrub was checked by rendering,
not only by byte search: every event was replayed through a headless
terminal and both screen buffers and the window titles searched for the
replaced terms and personal identifiers.

Format: `{"version":1,"cols":120,"rows":30,"events":[...]}`, each event
either `{"ms":N,"kind":"data","b64":"<bytes>"}` or
`{"ms":N,"kind":"resize","cols":C,"rows":R}`. Base64 keeps escape bytes and
CR/LF clear of git's line-ending handling. The stream enters the alternate
screen at event 16 and never leaves it.

`claude-session.cuts.json` is hand-written input shared by the Rust and JS
tests: `{"name","afterEvent"}` means "the state after events[0..=afterEvent]".

## The second recording: scrollback-session

`scrollback-session.json` is SYNTHETIC. The real Claude Code 2.1.327 session
above enters the alternate screen at event 16 and never leaves it, so it has
no scrollback history at all and cannot exercise styled history, wrapped
lines across the history/screen boundary, wide cells or resizes of a
scrolling main screen. This one lives on the main screen: about 200 styled
lines, wrapped lines, CJK/emoji (a wide character on the last column
included), OSC 8 links, a mode 2026 frame, resizes to 60x30 and 100x40, an
alternate-screen excursion and a prompt with the cursor left mid-line.
Some chunks split an escape sequence or a multi-byte character.

It is written by a deterministic script (no dates, no randomness; the
script is `make-scrollback-session.mjs`, run from the repo root):

    node crates/skein-daemon/src/pty/engine/fixtures/make-scrollback-session.mjs

The script prints the event index of each named mark; keep
`scrollback-session.cuts.json` in step with those by hand.

Files here: the two recordings, their two `*.cuts.json` files, the two
`*.engine.json` pictures, the two `*.frames.json` files and the script.

## The engine pictures: NAME.engine.json

GENERATED by the Rust replay (`replay_tests.rs`): each recording is replayed
through `AlacrittyEngine` (start size from the file, resize events resize,
replies are collected and not fed back, no real time: a synchronized update
ends only at the stream's own `?2026l`) and the terminal is pinned at every cut
of `NAME.cuts.json`. A JavaScript test replays the same events through
xterm.js and compares. Regenerate after an intended engine change and review
the diff:

    SKEIN_UPDATE_ENGINE_DUMPS=1 cargo test -p skein-daemon replay_tests

Layout, one style and one cut per line: `{"version":1,"fixture":NAME,
"styles":[...],"cuts":[...]}`.

- `styles[id]`: `{fg, bg, bold, italic, dim, underline, inverse, invisible,
  strikethrough}`. Index 0 is the default style. A colour is `"default"`,
  `{"p":0-255}` (a palette index: `ESC[31m` and `ESC[38;5;1m` are both
  `{"p":1}`) or `{"rgb":"rrggbb"}`. `underline` is any underline style.
- A cut: `{name, afterEvent, rows, cols, altScreen, cursor:{row,col,visible},
  modes, historyRowsEntered, rebuilds, history, screen}`; the state after
  `events[0..=afterEvent]`. Rows and columns are zero-based. `history` is the
  main screen's scrollback, oldest first (empty while `altScreen`: the engine
  cannot read the hidden main screen); `screen` is the active screen, top row
  first.
- `modes`: `app_cursor_keys`, `app_keypad`, `bracketed_paste`,
  `focus_reporting`, `mouse_tracking` (`off|click|drag|motion`),
  `sync_pending` are the ones xterm.js exposes publicly; also `mouse_encoding`
  (`default|utf8|sgr`), `alt_screen`, `cursor_visible`, `cursor_shape`
  (`block|underline|bar`), `cursor_blinking`, `kitty_keyboard_flags` as extra
  data. `sync_pending`: a `?2026` update is open and the grid does not show it
  yet.
- A row: `{"wrapped":bool,"runs":[...]}`. `wrapped` is true when the row
  continues the previous one (xterm.js `isWrapped`). A run is
  `[col, end, style, text]` or `[col, end, style, text, link]`: consecutive
  cells with one style and link, columns `col..end` (end exclusive, so
  `end - col` is the cell count). `text` is the cells' characters joined; a
  wide character appears once and spans two columns (its spacer cell is
  inside the run and adds no text); zero-width characters follow their base
  character. `link` is the OSC 8 URI. Blank cells inside a row are spaces in
  the text; trailing cells that are blank with the default style and no link
  are trimmed, so a row's runs may stop short of `cols`; blank cells with a
  non-default style (background) are kept.
- `historyRowsEntered` counts rows that entered history since the engine was
  created. It is exact only until the first resize while history holds rows
  (scrollback-session/resize-60x30: 192 entered, 202 present), so compare it
  only before a resize. `rebuilds` is how often the panic guard rebuilt the
  engine (0 throughout).

## The frames: NAME.frames.json

GENERATED by `redraw/tests_replay.rs` (#807): each recording is replayed as
above, and what the daemon would send is pinned: the redraw encoder's frames
for three viewers. A JavaScript test feeds them to `@xterm/headless` and
compares with xterm.js fed the raw stream. Regenerate with the same command
as the pictures (`SKEIN_UPDATE_ENGINE_DUMPS=1 cargo test -p skein-daemon replay`)
and review the diff; without the variable the test fails when the file differs.

Layout, one item per line: `{"version":1,"fixture":NAME,"cols":C,"rows":R,
"stream":[...],"cuts":[...]}`; `cols`/`rows` are the recording's start size.

- `stream`: in order, what one viewer attached from the start receives. A
  frame is `{"afterEvent":N,"kind":"frame","b64":"..."}`, cut after every data
  event and every resize event, listed only when the encoder sent something
  (nothing is cut inside a synchronized update). A resize is
  `{"afterEvent":N,"kind":"resize","cols":C,"rows":R}`: the engine's new size,
  listed before the frame cut after it, so the client resizes first.
- `cuts[]`: `{name, afterEvent, cols, rows, full, skipped}` for every cut of
  `NAME.cuts.json`. `cols`/`rows` are the engine's size there. `full` is the
  frame a fresh viewer gets then (the attach snapshot). `skipped` is the frame
  of a viewer that is framed only at the cuts, in order: a diff spanning
  everything since the previous cut, the first one being the full redraw.
  Both are base64, and an empty string when nothing was sent (a cut inside a
  synchronized update, `in-sync-frame`, sends nothing).
